怎麼把自己的工作流程做成 Claude skill？

問：我每次都對 AI 重複交代同一套做事步驟，能不能把它存成一份 skill，之後直接叫出來用？

可以。skill 就是一個資料夾，裡面放一份 SKILL.md，把你的做法寫成 Claude 可以照著做的指示。下面照 Anthropic 公開文件（2026 年 11 月查閱）說明做法與限制。

Q1：skill 的最小結構是什麼？

一個資料夾加一個 SKILL.md。檔案開頭是 YAML frontmatter（用 --- 包起來），後面是 Markdown 指示：

---
name: weekly-report
description: 把本週的 commit 與 issue 整理成週報。當使用者提到週報、週會摘要時使用。
---

1. 讀取本週合併的 PR 與關閉的 issue。
2. 依「完成、進行中、卡住」三段整理。
3. 每項附上連結，語氣精簡。

重點是 name 與 description。平台文件的規定：name 最多 64 字元，只能用小寫字母、數字與連字號，不能含 anthropic 或 claude 這兩個保留字；description 最多 1,024 字元，要同時寫「這個 skill 做什麼」與「什麼時候該用」。Claude Code 文件則寫得較寬鬆：所有欄位都是選填，只建議寫 description。兩份文件的說法不同，建議兩個欄位都照平台文件的規則寫，各個平台都過得去。

Q2：Claude 怎麼決定要不要用這份 skill？

靠 description。Anthropic 的說明是漸進式載入：一開始只把每個 skill 的名稱與描述放進上下文（文件估計每個約 100 個 token），Claude 判斷你的請求符合描述，才讀 SKILL.md 本文，需要時再讀資料夾裡的其他檔案。所以描述寫得太籠統，Claude 就不會想到要用它；把常見的說法、觸發情境寫進去，比把步驟寫得很長更有用。Claude Code 文件另提醒，description 加上 when_to_use 合計超過 1,536 字元，會在 skill 清單裡被截斷，最重要的用途要放前面。

Q3：可以放腳本和參考資料嗎？

可以，這是選用的。資料夾裡可以多放參考文件、範例，或 scripts/ 底下的腳本（例如 Python）。文件說明腳本是被執行而不是被讀進上下文，只有執行結果會進入對話，所以適合放需要每次都做得一模一樣的步驟，例如格式檢查。在 SKILL.md 裡要寫明什麼情況該讀哪個檔案，Claude 才知道何時去取。官方建議 SKILL.md 本文控制在 500 行內，細節拆到別的檔案。

Q4：存放在哪裡？

  • Claude Code：個人用放 ~/.claude/skills/<skill 名稱>/SKILL.md，只給某個專案用放該專案的 .claude/skills/<skill 名稱>/SKILL.md，後者可以提交進版本庫與團隊共用。
  • Claude.ai（網頁與 App）：把資料夾壓成 zip 上傳。依文件，這在 Pro、Max、Ultra、Team、Enterprise 等方案、且開啟程式碼執行功能時可用。
  • Claude API：透過 skills 相關端點上傳，搭配程式碼執行工具使用。

平台文件註明：自訂 skill 不會在 Claude.ai 與 API 之間同步，要各自上傳。例外是 Claude Code：用 claude.ai 帳號登入時，會把帳號裡啟用的 skill 單向下載到電腦上（Claude Code 文件，需 v2.1.273 以上）；你在電腦上寫的 skill 不會反過來上傳到 claude.ai。

Q5：把工作流程變成好用的 skill，有什麼實際建議？

這一段是經驗談，不是官方規定：

  1. 先從一個你每週都在重複的任務開始，不要一開始就想包山包海。
  2. 指示寫成可檢查的步驟，例如「輸出一定要有三個段落」，比「寫得專業一點」好驗證。
  3. 把「什麼時候不要用」寫進描述，避免誤觸發。
  4. 用真實任務試跑，看 Claude 有沒有照步驟做，再回頭改指示。
  5. 只裝來源可信、你也讀過內容的 skill。 官方文件建議只用可信來源的 skill：你自己寫的，或 Anthropic 提供的。來源不明的要格外小心，完整檢視 SKILL.md、腳本、圖片與其他資源，留意預期之外的網路請求、檔案存取，或和它說的用途不符的操作；文件提醒，惡意 skill 可能造成資料外洩或未經授權的存取。我們另外建議：讀過內容也不代表沒有風險，自己寫的也一樣，先在不重要的資料上試用。
